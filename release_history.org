* Release History

** v0.4.0 - 2026-09-24
*** Release Summary
- Deliver Phase 1 Stage 1.3 with account registration, login sessions, and bilingual login UI.

*** Changes
- Add account, user setting, and revocable session tables through the second SQLite migration.
- Add case-insensitive username registration, salted PBKDF2 password verification, and seven-day server-side sessions.
- Add Dioxus registration, login, logout, and current-user endpoints with host-only cookies and origin checks.
- Add bilingual account UI, authentication tests, and deployment origin guidance.

*** Compatibility and Upgrade Notes
- Set =ZETA_PRACTICE_PUBLIC_ORIGIN= to the external HTTPS origin for deployment; local development defaults to =http://127.0.0.1:8080=. Back up the SQLite database before this forward-only migration. Full build and live browser flow were not run.

** v0.3.1 - 2026-09-24
*** Release Summary
- Adapt the Rust workspace to the Forge toolchain and approved dependency catalog.

*** Changes
- Replace the legacy baseline selector with schema 2 capability selection and remove obsolete workspace baseline metadata.
- Clarify current catalog ownership in the architecture documents while retaining historical Stage 1.1 notes.
- Synchronize the workspace package, lockfile, and repository version.

*** Compatibility and Upgrade Notes
- Use the current Forge build engine with the schema 2 =zeta-rust.toml= configuration. Builds and tests were not rerun for this commit.

** v0.3.0 - 2026-09-24
*** Release Summary
- Deliver Phase 1 Stage 1.2 with server-side SQLite initialization and ordered migrations.

*** Changes
- Require an explicit persistent =ZETA_PRACTICE_DB_PATH= and initialize SQLite before the server starts.
- Apply numbered migrations transactionally, record migration history, and reject incompatible history or failed SQL.
- Add storage metadata as the first infrastructure migration and verify replay, rollback, and restart persistence.
- Adopt the Forge =1.97.1-r3= baseline with governed =rusqlite 0.40.2=.

*** Compatibility and Upgrade Notes
- Server startup now requires an absolute database file path whose parent directory exists. Domain tables remain for later Stages.

** v0.2.1 - 2026-09-24
*** Release Summary
- Add a unified Forge-backed build entry for the Web/fullstack application.

*** Changes
- Add the root =zbuild.py= launcher and project-owned Rust build definition.
- Document build, check, test, run, dev, profile, and output contracts in =BUILD.org= and link it from the project READMEs.
- Adopt the immutable Forge Rust baseline =1.97.1-r1=.

*** Compatibility and Upgrade Notes
- The application behavior is unchanged; build commands now use the unified root entry.

** v0.2.0 - 2026-09-20
*** Release Summary
- Deliver Phase 1 Stage 1.1 with the first runnable Rust/Dioxus Web/Fullstack application foundation.

*** Changes
- Added a forge-managed Rust 1.97.1 workspace with one application member and a committed Cargo lockfile.
- Added typed Home and About routes with a responsive bilingual zh-CN/en-US application shell.
- Adopted the new forge =dioxus-web-fullstack= dependency group and root toolchain override for Cargo and Dioxus CLI consistency.
- Recorded Stage 1.1 acceptance evidence from forge doctor, offline locked metadata, check, test, fullstack startup, HTTP routes, and browser locale interaction.

*** Compatibility and Upgrade Notes
- This release adds the application foundation only; authentication, database persistence, and typing behavior remain intentionally absent.

** v0.1.1 - 2026-09-20
*** Release Summary
- Reframe the typing roadmap as Phase 1 with acceptance-driven Stages independent of release-version numbering.

*** Changes
- Replaced the version-bound typing plan with a bilingual Phase 1 plan covering 12 cohesive implementation and acceptance Stages.
- Recorded Stage ownership, dependencies, non-goals, acceptance evidence requirements, and actual delivery-version fields without preallocating future versions.
- Kept the =zeta_forge= Web/Fullstack dependency baseline as an explicit external prerequisite and added mappings from the superseded plan identifiers.
- Updated the architecture and bilingual documentation indexes to use Phase terminology and the new plan paths.
- Ignored local =.vorg.db= editor database files.

*** Compatibility and Upgrade Notes
- This release changes planning documentation only; it does not add a production application, database schema, public API, or deployment artifact.

** v0.1.0 - 2026-09-20
*** Release Summary
- Establish the initial project definition and architecture baseline for a Web-first, multi-user skill practice platform.

*** Changes
- Defined the product scope around practice, measurement, feedback, and capability improvement rather than basic instructional content.
- Selected a Web-first Rust/Dioxus direction with a browser-local practice hot path and server-side authentication, persistence, statistics, and adaptive profile state.
- Kept SQLite as the initial server database and documented a single-service deployment model with persistent storage.
- Defined independent practice-module ownership and deferred a generic practice framework until a second real module demonstrates shared abstractions.
- Adopted the ZetaX Rust governance model: public Rust dependencies and toolchains are managed by =zeta_forge= while this repository owns application source, workspace structure, feature choices, and =Cargo.lock=.
- Added the =v0.2.0= typing MVP implementation plan, including the required =zeta_forge= Web/Fullstack dependency-baseline prerequisite.

*** Compatibility and Upgrade Notes
- This is a documentation and project-baseline release. No production application, database schema, public API, or deployment artifact exists yet.
