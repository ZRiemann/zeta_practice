* 目标

=v0.2.0= 交付第一个完整可用闭环：

#+begin_src text
打开 Web 应用
  -> 登录
  -> 开始 typing practice
  -> 浏览器本地完成输入
  -> 结束并提交结果
  -> 持久化结果
  -> 更新统计/profile
  -> 根据当前能力生成下一次练习
#+end_src

typing 是能力练习系统，不承担基础键盘教学。键位、指法、姿势等基础知识由用户人工教学
或其他材料完成。

* 明确不做

v0.2.0 不包含：

- 键位和指法教学；
- curriculum tree、mastery graph、lesson unlock；
- 游戏经济、排行榜、社交和复杂成就；
- AI tutor 或模型推荐；
- offline sync；
- PostgreSQL、Redis、消息队列和微服务；
- 复杂 Parent/RBAC 管理流程。

* Stage 0 - Zeta Forge 前置任务

在本仓库加入正式 Cargo manifest 之前：

1. 在 =zeta_forge/rust/baseline.toml= 增加经过审查的 Dioxus Web/Fullstack 依赖组。
2. 保持 forge 当前受管 Dioxus 版本策略；如果要升级，必须先在 =zeta_forge= 完成。
3. server、SQLite、密码哈希、序列化、时间和 migration 等公共 crate 如需使用，先纳入 forge 治理。
4. 验证 zeta_forge Rust 基线和自身测试。
5. 然后才在 =zeta_practice= 创建 =zeta-rust.toml= 和项目 Cargo workspace。

这是跨仓库前置任务；=zeta_practice= 不能通过自己 pin 一套公共 crate 版本来绕过它。

* Stage 1 - 最小 Rust/Dioxus 应用基础

首版只建立一个 Rust workspace 和一个正式 application member。
auth、storage、typing 暂时保持为应用内部 module，不为了形式提前拆多个 crate。

建议逻辑布局：

#+begin_src text
Cargo.toml
Cargo.lock
zeta-rust.toml
rust/
  rust-toolchain.toml
app/
  Cargo.toml
  src/
    main.rs
    app.rs
    auth/
    storage/
    i18n/
    typing/
      model.rs
      generator.rs
      session.rs
      statistics.rs
      profile.rs
      ui.rs
#+end_src

真正实施时，Dioxus client/server 文件布局以 forge 受管版本和可执行工具为准。

验收：

- forge =rust doctor= 通过；
- forge =rust metadata= 按 =--locked --offline= 语义通过；
- Dioxus Web 应用可启动；
- server 使用显式数据库路径启动；
- =zh-CN= / =en-US= UI 切换可用。

* Stage 2 - 认证和持久化基础

只实现 typing 闭环真正需要的数据。

初始概念表：

#+begin_src text
users
user_settings
auth_sessions
typing_sessions
typing_session_char_stats
typing_profiles
#+end_src

=users= 保存身份和 password hash，绝不保存明文密码。
=auth_sessions= 保存可撤销的服务端登录 session。
=typing_sessions= 保存一次完整练习摘要。
=typing_session_char_stats= 保存本次每个字符的 attempts/errors，不保存每个原始按键事件，
同时可以计算近期弱项。
=typing_profiles= 保存当前小型 adaptive 状态。

从第一版数据库开始使用显式 schema migration。

验收：

- 多用户 create/login/logout 可用；
- 用户不能读取或写入其他用户的练习数据；
- 服务重启后账户和练习历史仍存在；
- migration 可重复验证并有测试。

* Stage 3 - Typing Session Engine

初始练习类型：

1. 大小写字母综合练习；
2. 根据难度加入数字和基础标点的综合字符练习；
3. 单词；
4. 短句。

浏览器一次获取 =PracticeSpec=，完整 keyboard loop 都在本地执行。

建议领域概念：

#+begin_src rust
PracticeType
PracticeSpec
PracticeResult
CharacterStat
TypingProfile
Difficulty
#+end_src

Dioxus component state 不能直接充当领域模型。

** 指标契约

先固定指标，再实现 UI：

- =duration_ms=：单调时钟测量的有效练习时长；
- =attempt_count=：session 语义下计入统计的可打印字符输入次数；
- =correct_count=：按固定 cursor/correction 规则判定正确的次数；
- =error_count=：错误次数；
- =accuracy=：attempt 非零时 =correct_count / attempt_count=；
- =completed_characters=：成功完成的目标字符数量；
- =wpm=：=(completed_characters / 5) / active_minutes=；
- =correction_count=：如支持修正行为，单独统计。

错误按键和 Backspace 对 cursor 的具体影响必须由测试固定，UI 重构不能改变统计语义。

练习耗时使用浏览器 monotonic timer。墙上时间只用于持久化时间戳，不用于 WPM。

* Stage 4 - Statistics 与 Adaptive Profile

第一版算法保持 deterministic、可解释。

Profile 保持小型：

#+begin_src text
recent_accuracy
recent_wpm
difficulty
weak_characters
last_practiced_at
#+end_src

弱项统计使用有限近期窗口，不能让很久以前的数据永久主导当前能力判断。

初始策略可以使用集中定义的默认值：

#+begin_src text
近期稳定 accuracy >= 95% -> 可以提高 difficulty
accuracy < 85%           -> 降低复杂度或增加弱项强化
其他                     -> 保持 difficulty
#+end_src

动态字符练习对弱字符增加有限权重，例如默认普通字符/弱字符约 70/30。
这些值属于集中策略配置，不允许作为 UI magic number 散落。

WPM 是次级进阶信号。不能为了提高速度奖励持续较差的准确率。

* Stage 5 - 内容

内容保持简单：

#+begin_src text
assets/
  typing/
    en-US/
      words.*
      sentences.*
#+end_src

字符综合练习由 =PracticeSpec + TypingProfile= 动态生成。
单词/短句来自仓库版本化资源，也可以优先选择包含当前弱字符的内容。

v0.2.0 不建立 curriculum 数据库。

* Stage 6 - Web UI

Typing 主页面保持精简：

#+begin_src text
+--------------------------------------+
| Practice type / progress             |
+--------------------------------------+
|                                      |
|              Target text             |
|              User input              |
|                                      |
+--------------------------------------+
| Accuracy       WPM        Time        |
+--------------------------------------+
| Progress / concise adaptive hint     |
+--------------------------------------+
#+end_src

不需要虚拟键盘、手指动画、键位课程或复杂游戏 UI。

结束页面回答三个问题：

- 本次表现如何？
- 哪些字符较弱？
- 下一步练什么？

* Server API 边界

使用 forge 受管 Dioxus 版本提供的 typed client/server 边界。
在没有明确非 Dioxus client 需求之前，不额外发明第二套 REST API。

最小操作概念上包括：

#+begin_src text
login / logout / current_user
start_practice
submit_practice_result
recent_typing_history
typing_profile
#+end_src

=start_practice= 一次性返回有界的练习规格/内容。
=submit_practice_result= 提交完成摘要和字符级计数，不逐键联网，也不上传无限增长的原始事件流。

服务端必须校验用户归属、计数关系、payload 上限以及 practice/difficulty 合法值。

* 验证

重点自动测试：

- 使用固定 seed 时 generator 可确定复现；
- target matching 和 correction 语义；
- zero-duration / zero-attempt 安全；
- Accuracy / WPM 计算；
- 字符错误统计；
- adaptive 阈值转换；
- 弱字符加权边界；
- 多用户认证隔离；
- SQLite migration 和重启持久化；
- server payload 校验；
- 中英文 route/component smoke test。

Rust doctor、metadata、check、build、test 统一使用 =zeta_forge= 入口。
没有真实浏览器运行验证时，不能宣称 Web runtime 已验证。

* 完成定义

=v0.2.0= 完成时，至少两个独立用户能够通过 Web 应用登录，在无逐键网络请求的情况下完成
typing 练习，分别持久化自己的历史，查看 Accuracy/WPM/error 统计，并根据近期表现得到
确定性的下一次练习调整。

第二个练习模块不属于本版本。
