** 持久化模型

只实现 typing 闭环真正需要的数据。

初始概念表：

#+begin_src text
users
user_settings
auth_sessions
typing_sessions

*** 指标契约

先固定指标，再实现 UI：

- =duration_ms=：单调时钟测量的有效练习时长；
- =attempt_count=：session 语义下计入统计的可打印字符输入次数；
- =correct_count=：按固定 cursor/correction 规则判定正确的次数；
- =error_count=：错误次数；
- =accuracy=：attempt 非零时 =correct_count / attempt_count=；
- =completed_characters=：成功完成的目标字符数量；
- =wpm=：=(completed_characters / 5) / active_minutes=；
- =correction_count=：如支持修正行为，单独统计。

错误按键和 Backspace 对 cursor 的具体影响必须由测试固定，UI 重构不能改变统计语义。

练习耗时使用浏览器 monotonic timer。墙上时间只用于持久化时间戳，不用于 WPM。

** 自适应策略

第一版算法保持 deterministic、可解释。

Profile 保持小型：

#+begin_src text
recent_accuracy
recent_wpm
difficulty
weak_characters
last_practiced_at
#+end_src

弱项统计使用有限近期窗口，不能让很久以前的数据永久主导当前能力判断。

初始策略可以使用集中定义的默认值：

#+begin_src text
近期稳定 accuracy >= 95% -> 可以提高 difficulty
accuracy < 85%           -> 降低复杂度或增加弱项强化
其他                     -> 保持 difficulty
#+end_src

动态字符练习对弱字符增加有限权重，例如默认普通字符/弱字符约 70/30。
这些值属于集中策略配置，不允许作为 UI magic number 散落。

WPM 是次级进阶信号。不能为了提高速度奖励持续较差的准确率。

Phase 1 不建立 curriculum 数据库。

** UI 边界

Typing 主页面保持精简：

#+begin_src text
+--------------------------------------+
| Practice type / progress             |
+--------------------------------------+
|                                      |
|              Target text             |
|              User input              |
|                                      |
+--------------------------------------+
| Accuracy       WPM        Time        |
+--------------------------------------+
| Progress / concise adaptive hint     |
+--------------------------------------+
#+end_src

不需要虚拟键盘、手指动画、键位课程或复杂游戏 UI。

结束页面回答三个问题：

- 本次表现如何？
- 哪些字符较弱？
- 下一步练什么？

** Server API 边界

使用 forge 受管 Dioxus 版本提供的 typed client/server 边界。
在没有明确非 Dioxus client 需求之前，不额外发明第二套 REST API。

最小操作概念上包括：

#+begin_src text
login / logout / current_user
start_practice
submit_practice_result
recent_typing_history
typing_profile
#+end_src

=start_practice= 一次性返回有界的练习规格/内容。
=submit_practice_result= 提交完成摘要和字符级计数，不逐键联网，也不上传无限增长的原始事件流。

服务端必须校验用户归属、计数关系、payload 上限以及 practice/difficulty 合法值。

* 验证

重点自动测试：

- 使用固定 seed 时 generator 可确定复现；
- target matching 和 correction 语义；
- zero-duration / zero-attempt 安全；
- Accuracy / WPM 计算；
- 字符错误统计；
- adaptive 阈值转换；
- 弱字符加权边界；
- 多用户认证隔离；
- SQLite migration 和重启持久化；
- server payload 校验；
- 中英文 route/component smoke test。

Rust doctor、metadata、check、build、test 统一使用 =zeta_forge= 入口。
没有真实浏览器运行验证时，不能宣称 Web runtime 已验证。

* Phase 验收

=Phase 1= 完成时，至少两个独立用户能够通过 Web 应用登录，在无逐键网络请求的情况下完成
typing 练习，分别持久化自己的历史，查看 Accuracy/WPM/error 统计，并根据近期表现得到
确定性的下一次练习调整。

第二个练习模块不属于本 Phase。

Stage 1.12 记录集成证据。所有前置 Stage 及完整闭环必须通过必要检查后才能验收
Phase。最后一个 Stage 与 Phase 同时版本化交付时，在同一次交付中记录两者。
