#+TITLE: zeta_practice build entry

* Unified build entry
The root entry uses =./zbuild.py <command> [deliverable ...] --profile release|debug=.
The profile defaults to =release=. Run =./zbuild.py list= for targets and capabilities,
and append =--dry-run= to inspect scope without executing. Unsupported actions fail.
=check= performs non-mutating source/compiler checks; =test= prepares and runs native
correctness suites. =run= requires an existing output; =dev= builds and runs (or
uses the application's native watcher). Arguments after =--= are forwarded without
logging. Cleanup affects the owning native engineering unit and selected profile;
the plan names affected sibling outputs. Installations, data and shared caches stay intact.
Host preparation and deployment are separate operations.

Default build/run: =zeta-practice=, the complete Dioxus Web/fullstack application.
=build= creates both client and server plus public assets; =check= separately
checks host server and wasm web features (including Clippy) after rustfmt.
=test= uses host-runnable server-feature tests, not a wasm/browser harness.
=dev= uses locked Dioxus serve with its native watcher.
#+begin_src sh
./zbuild.py doctor
./zbuild.py check --profile debug
./zbuild.py test --profile debug
./zbuild.py build
./zbuild.py run
./zbuild.py dev --profile debug
#+end_src
Built release server: =target/dx/zeta-practice/release/web/server=, assets beside it
in =public/=. =run= preserves resource lookup and defaults to local =127.0.0.1:8080=;
=IP= and =PORT= can override it. Missing output fails without recompilation.

* SQLite runtime path

The server requires =ZETA_PRACTICE_DB_PATH= to be an absolute path to a database
file on persistent storage. Create its parent directory before starting the
server; startup opens the file and applies pending schema migrations. Startup
fails with a migration error rather than serving with an unsupported schema.
The Web client does not open SQLite. Back up the database file before upgrading
to a release with new migrations; schema migrations are forward-only.

#+begin_src sh
ZETA_PRACTICE_DB_PATH=/srv/zeta-practice/practice.sqlite ./zbuild.py run
#+end_src

* Authentication origin and cookies

Registration, login, and logout require an =Origin= matching
=ZETA_PRACTICE_PUBLIC_ORIGIN=. For local development the default is
=http://127.0.0.1:8080=; use that exact address in the browser. Set this
variable to the externally visible HTTPS origin in deployment, without a
trailing slash or path. Non-local HTTP origins are rejected at startup.
HTTPS sets =Secure= on the host-only, =HttpOnly=, =SameSite=Lax= session cookie.
The cookie expires after seven days; logout revokes only its current session.
Usernames are case-insensitive and use 3-32 ASCII letters, digits, underscores,
or hyphens. Passwords use 12-128 UTF-8 bytes and are stored as salted PBKDF2
hashes. Accounts are created through the public bilingual registration form.
